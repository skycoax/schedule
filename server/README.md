# Бэкенд расписания КФУ

Node + SQLite. Воркер раз в несколько минут читает источник расписания, кладёт в
базу, а приложение читает **из базы** — быстро и не завися от Google.

## Что внутри

| Файл | Зачем |
|---|---|
| `src/index.js` | HTTP-слой (Fastify) и маршруты API |
| `src/poller.js` | воркер: периодически перечитывает источник |
| `src/source.js` | **единственное место**, завязанное на источник данных |
| `src/store.js` | снимки расписания, сравнение, журнал изменений |
| `src/schedule.js` | сборка ответа + «сейчас» по Ташкенту |
| `src/analytics.js` | заходы: разбор UA, псевдоним IP, сводка |
| `src/db.js` | SQLite (встроенный `node:sqlite`, без нативных сборок) |

## Запуск локально

```bash
cd server
npm install
cp .env.example .env      # и заполнить ADMIN_PIN, IP_SALT
npm start                 # http://127.0.0.1:8790
```

Требует **Node ≥ 22** (для встроенного SQLite). Флаг `--experimental-sqlite`
уже прописан в `npm start`.

## API

| Маршрут | Что делает |
|---|---|
| `GET /api/health` | жив ли, когда была последняя сверка |
| `GET /api/schedule` | расписание из базы + «сейчас» + журнал правок |
| `GET/POST /api/hit` | записать заход (аналитика) |
| `GET /api/stats?pin=…` | сводка статистики (только с ПИНом) |
| `GET /api/refresh?pin=…` | ручная внеплановая сверка |

## Про источник

Таблица вуза приватная — сервер не может прочитать её напрямую. Поэтому
`src/source.js` пока берёт уже разобранный JSON у публичного эндпоинта Apps Script
(он читает таблицу под аккаунтом владельца). Когда/если подключим сервисный
Google-аккаунт с доступом к таблице — меняется только этот файл, остальное как есть.

## Про аналитику — честно

Собираем то, что видит любой веб-сервер (IP, User-Agent, referrer) плюс присланное
страницей (группа, экран, язык, метка источника). При этом:

- **сырой IP не хранится** — только соль+хеш (для дедупликации) и вид с обнулённым
  последним октетом (для грубой географии);
- ничего личного (имя, почта, телефон, координаты) не собирается;
- всё раскрыто в политике приложения, данные обезличены.

## Развёртывание на VPS (потребует разовый sudo)

Node на сервере ещё нет. Порядок (Node ставится **без sudo** через nvm, sudo нужен
только для nginx и автозапуска):

```bash
# 1. Node без sudo (nvm):
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc && nvm install 22

# 2. Код и зависимости:
#    (файлы приезжают через scp из deploy-скрипта; тут — npm install)
cd ~/kfu-server && npm install --omit=dev

# 3. Автозапуск (pm2, тоже без sudo, кроме одной строки для systemd):
npm i -g pm2
pm2 start "npm start" --name kfu-api
pm2 save
pm2 startup        # напечатает ОДНУ команду с sudo — её выполнить

# 4. Проксирование в nginx (sudo): в блок сайта kfu.* добавить
#    location /api/ { proxy_pass http://127.0.0.1:8790; }
#    затем sudo nginx -t && sudo systemctl reload nginx
```

Тогда приложение и API живут на одном домене (`/api/…`) — без CORS и без отдельного
сертификата.

# Расписание на своём сервере

Здесь лежит собранная страница для твоего домена — та же, что и в Apps Script.
Правки всегда вносятся в `../apps-script/Index.html`, отсюда файл только собирается.

## Зачем переносить

| | Apps Script `/exec` | Свой домен |
|---|---|---|
| Полосы под чёлкой и синяя плашка Google | есть, изнутри не убрать | нет |
| Открытие | ~20–30 сек (грузится фрейм Google) | доли секунды |
| Откуда пришёл человек | не видно, у всех «Прямой заход» | видно по-настоящему |
| Кнопка «Установить» в Chrome | не появляется | появляется |
| Настройки в браузере | стираются: домен каждый раз новый | живут нормально |
| Адрес | `script.google.com/macros/s/AKfy…` | `kfu.bestcenter.uz` |

Причина у всего одна: по ссылке `/exec` страница живёт в чужом фрейме на домене,
который Google выдаёт заново каждый сеанс. Ни фон верхнего документа, ни хранилище
браузера, ни referrer оттуда не достать.

## 1. Доступ к API — уже открыт

Страница берёт расписание из Apps Script по JSON. Развёртывание уже стоит на
«Все», и заголовок `Access-Control-Allow-Origin: *` отдаётся — проверено запросом
с постороннего домена. Проксировать через nginx не нужно.

Проверить в любой момент:

```bash
curl -sL "https://script.google.com/macros/s/AKfycbw3Q_91thWAajWY1YVjOSrBrDA4tzjfmCYN7W3x4NSV_cGo-u4VF-Z5dvjjUXJFiRGg/exec?fn=data" | head -c 120
```

Должно начаться с `{"ok":true,"data":…`.

## 2. Токен на запись *(необязательно)*

Без токена страница читает расписание, а выбор группы и уведомления хранит только
в браузере — этого хватает. Токен нужен, если хочешь, чтобы выбор группы уезжал
на сервер и Telegram-бот знал, за какой группой следить.

1. Apps Script → функция **`makeApiToken`** → **Выполнить**.
2. В журнале появится `API_TOKEN: …` — скопировать.
3. Вписать в `build_site.py` в переменную `TOKEN`, затем `python build_site.py`.

## 3. Выложить файлы

Нужны **все пять** — без манифеста и иконок Chrome не предложит установку:

```
index.html
manifest.json
icon-192.png
icon-512.png
icon-maskable-512.png
```

### DNS — уже сделано

`kfu` смотрел на проксируемый Cloudflare-wildcard `*.bestcenter.uz`, из-за чего
любой запрос падал с 526 (сертификата под `kfu` там взяться неоткуда). Запись
`A kfu → 46.8.195.171` с серым облаком (DNS only) добавлена и проверена —
домен теперь бьёт прямо в сервер, как `info.bestcenter.uz` и `bestcenter.uz`.

### Установка

SSH-ключ уже настроен, поэтому загрузка файлов идёт без пароля. Но сама установка —
создание `/var/www/kfu`, подключение конфига nginx, сертификат — требует `sudo`,
а `sudo` спрашивает пароль интерактивно. Через `ssh host "команда"` (без живого
терминала) это физически не проходит: `sudo` отвечает "a terminal is required to
authenticate" и всё останавливается — так и должно быть, это не баг.

Поэтому первый раз — двумя частями.

**Часть автоматическая** — из папки проекта, **на Windows** (PowerShell):

```powershell
.\deploy.ps1 -Full
```

(на Linux/macOS — `bash deploy.sh --full`). Скрипт соберёт страницу и зальёт все пять
файлов в `/tmp` на сервере — это не требует sudo. Дальше он сам увидит, что
`/var/www/kfu` ещё не готов, и выведет ровно те команды из части ниже.

**Часть ручная** — сам, один раз, за 30 секунд. Заходишь на сервер:

```bash
ssh ubuntu@46.8.195.171
```

и там, одной строкой (спросит пароль один раз):

```bash
sudo mkdir -p /var/www/kfu && sudo mv /tmp/index.html /tmp/manifest.json /tmp/icon-192.png /tmp/icon-512.png /tmp/icon-maskable-512.png /var/www/kfu/ && sudo chown -R ubuntu:ubuntu /var/www/kfu && sudo mv /tmp/kfu.bestcenter.uz.nginx /etc/nginx/sites-available/kfu.bestcenter.uz && sudo ln -sf /etc/nginx/sites-available/kfu.bestcenter.uz /etc/nginx/sites-enabled/ && sudo nginx -t && sudo systemctl reload nginx
```

Затем сертификат (тоже спросит пароль):

```bash
sudo certbot --nginx -d kfu.bestcenter.uz
```

**HTTPS обязателен:** без него не будет ни установки на главный экран, ни манифеста.

`chown -R ubuntu:ubuntu` здесь — не мелочь для красоты, а вся суть: после него папка
принадлежит тебе, и каждое дальнейшее обновление страницы `.\deploy.ps1` (уже без
`-Full`) делает без единого пароля. Тот же приём, что и у `/var/www/info-status` —
на этом сервере он уже используется.

### На сервере есть своя панель управления доменами — `domctl`

Все остальные поддомены (`info.bestcenter.uz`, `sky.bestcenter.uz` и другие —
видно по `/etc/nginx/sites-available/domctl-*.conf`) добавлены через неё. Она
тоже спрашивает sudo-пароль, так что обхода `sudo` это не даёт — но, возможно,
тебе привычнее добавить домен через неё, если знаешь, как её вызывать. Судя по
`/etc/domctl/domains.json`, она рассчитана на проксирование на порт
(`"proxy": "127.0.0.1:8080"`), а не на голую раздачу файлов — не факт, что для
статической страницы подойдёт без правок напрямую. Поэтому я выбрал более простой
путь выше: обычный nginx-конфиг, без завязки на неё. Если решишь всё же через
`domctl` — конфиг у него будет называться `domctl-kfu.bestcenter.uz.conf`, и в
`build_site.py`/`deploy.ps1` менять ничего не придётся, они не привязаны к имени
файла конфига.

## 4. После переезда

- Ссылку из подвала («Добавить на главный экран») страница строит уже от своего
  адреса, а не от Apps Script — раздавать одноклассникам нужно новую.
- Ссылка `/exec` продолжает работать: те, кто уже добавил её на экран, ничего
  не заметят. Выключать старое развёртывание не надо — на нём же держится
  подписка календаря (`?fn=ics`) и почасовая проверка расписания.
- В статистике вместо сплошного «Прямой заход» появятся настоящие источники.
  Метки в ссылке (`?from=tg`, `?from=ig`, `?from=qr`) продолжают работать и точнее
  referrer’а — их стоит вешать на посты и QR-коды.

## Обновление после правок

Поправил `apps-script/Index.html` — и одной командой:

```powershell
.\deploy.ps1
```

Иконки и манифест перезаливать не нужно — они не меняются.

## Что где

| Файл | Зачем |
|---|---|
| `apps-script/Index.html` | **исходник** — правки только сюда |
| `build_site.py` | сборка: адрес API, токен, манифест, карточка ссылки |
| `deploy.ps1` | выкладка на сервер (Windows) |
| `deploy.sh` | то же для Linux/macOS |
| `site/index.html` | собранная страница для сервера |
| `site/manifest.json`, `site/icon-*.png` | чтобы приложение ставилось на телефон |
| `site/kfu.bestcenter.uz.nginx` | готовый конфиг nginx |

## Если что-то не работает

| Симптом | Причина |
|---|---|
| «Не удалось получить расписание» | развёртывание не на «Все» либо адрес API в `build_site.py` устарел |
| Не появляется кнопка «Установить» | нет HTTPS, либо не залиты `manifest.json` и иконки |
| Нет своих иконок на главном экране | не залиты `icon-192.png` / `icon-512.png` |
| В статистике всё ещё «Прямой заход» | человек пришёл по прямой ссылке — так и должно быть |

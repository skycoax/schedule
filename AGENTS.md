# Расписания вузов — инструкция для ИИ-агентов (Codex, Claude и др.)

**Текущее состояние и что делать дальше — `docs/HANDOFF.md`.**

Неофициальное PWA-приложение расписания для студентов. Один сервер обслуживает
несколько вузов: какой показать, он решает по адресу (`kfu.skycoax.uz` → вуз `kfu`,
`tsue.skycoax.uz` → вуз `tsue`). Интерфейс на русском.

## Как устроено

```
web/                      React 19 + TypeScript + Vite. ОДНА сборка на все вузы.
  src/brand.ts            бренд вуза приходит от сервера (JSON в index.html), не хардкодить
server/                   Node 22 + Fastify + node:sqlite (флаг --experimental-sqlite)
  src/index.js            маршруты; вуз запроса = req.tenant (по заголовку Host)
  src/tenants.js          загрузка и проверка tenants/*/tenant.json
  src/site.js             index.html с брендом вуза, /manifest.json, /brand/* картинки
  src/source.js           выбор источника расписания по tenant.source.type
  src/source-edupage.js   адаптер EduPage (публичное расписание *.edupage.org)
  src/store.js            снимки, сравнение (журнал правок)
  src/schedule.js         ответ /api/schedule (недели A/B, лёгкий режим ?group=)
  src/together.js         совместные пары (поток): у выбранной группы поле with — с кем
                          она в той же аудитории в то же время (фронт: DayCard, Hero)
  src/analytics.js, reviews.js — статистика и отзывы (у каждого вуза своя база)
  src/social/             «Обсуждения» Para: аккаунты, лента, профили, модерация (одна база social.db)
  test/                   дымовой тест и наполнение «Обсуждений» (на сервер не выкладываются)
  tenants/<id>/           ВУЗ = эта папка: tenant.json + 7 картинок бренда
  tenants/_tools/brand-images.py  генератор картинок из логотипа
  tenants/README.md       короткая инструкция для человека
deploy/deploy.sh          ЕДИНСТВЕННЫЙ актуальный способ выкладки
```

Прод: VPS `ubuntu@46.8.195.171`, служба `schedule-api` (порт 8792), код в
`~/schedule-server`, сайт в `/var/www/schedule`, базы `~/schedule-server/data/<id>.db`.
nginx и wildcard-сертификат `*.skycoax.uz` уже настроены: **новый вуз не требует
правок nginx, DNS, сертификатов или systemd.**

### Para — общий адрес для всех вузов

`para.skycoax.uz` — нейтральное приложение **Para**: без эмблем и названий вузов в бренде
(чтобы не выглядеть официальным приложением вуза; готовится к Google Play как TWA).
- `server/hub/hub.json` — адрес, тексты Para и `redirectOldHosts`; картинки бренда — там же,
  их рисует `python server/hub/make-icons.py`. `assetlinks.json` для Android кладётся туда же.
- `server/src/hub.js` — на адресе Para вуз берётся из `?uni=<id>`, иначе из куки `uni`.
  API на этом адресе без выбранного вуза отвечает 404 «Вуз не выбран».
- Фронт: `brand.hub = true`; пока вуз не выбран (`brand.id` пуст) — экран
  `UniversityStart.tsx`. `lib/uni.ts` хранит выбор в `store('uni')`, группу/преподавателя
  каждого вуза откладывает в `prev_<id>`; `api.ts` добавляет `uni=` ко всем запросам.
- При `redirectOldHosts: true` страница старого адреса (`kfu.skycoax.uz`…) переносит
  человека в Para вместе с настройками (во фрагменте `#m=`); API старых адресов работает.
  Согласие (`agreed`) и `cid` не переносятся; `#m=` Para принимает только при `redirectOldHosts: true`
  и только со страницы старого адреса (по `document.referrer`), — ссылкой с `#m=` экран согласия не обойти.
- Без интернета: `web/public/sw.js` (страница и API — сначала сеть, иначе сохранённое;
  сохранённый ответ помечен `x-para-saved`, тогда «сейчас» считает `lib/now.ts`).
- Новый вуз появляется в Para сам (из `tenants/`), эмблема для Para не нужна.

### Обсуждения (Para и адреса вузов)

Аккаунты (вход через Google), лента «Обсуждения», профили, друзья, жалобы и модерация. Адрес вуза
(`kfu.skycoax.uz`…) — **та же Para с уже выбранным вузом** и его эмблемой: те же нижние вкладки, вход и лента
(бренд вуза получает `social`, см. `site.js` `pageHtml`, фронт — `hasSocial` в `brand.ts`). База и аккаунт одни,
а сессия (кука `__Host-`) у каждого адреса своя. Google возвращает только на Para (redirect_uri один):
вход, начатый на адресе вуза, Para завершает обменом кода и передаёт адресу вуза одноразовым билетом
(`/api/auth/google/finish`, 2 минуты, в памяти); сессию создаёт адрес вуза, проверив куку входа этого браузера.
Поэтому новый вуз не требует настроек в Google Cloud. Запись (`POST/PATCH/DELETE`) каждый адрес принимает только
со своей страницы (Origin). Разработка: `<id вуза>.localhost` при `DEV_HUB=1` — адрес этого вуза.
Контракт — `docs/social/CONTRACT.md` (разделы B API, C база, F подключение); фронт — `web/src/social/`.

```
server/src/social/
  index.js       registerSocial(): хуки (только Para → CSRF → сессия), парсеры, 404 на неизвестные адреса
  http.js        ошибки с кодами, проверки S/P/N/M/A/U, куки, CSRF (X-Para + Origin), обработчик ошибок
  auth.js        /api/auth/*: me, вход через Google (PKCE, nonce, одноразовый state, передача входа адресу вуза),
                 выход, вход разработчика
  users.js       Me, @имена, профили, поиск, друзья, блокировки, PATCH /me, удаление аккаунта (маршрут)
  posts.js       лента, ветки, публикации, ответы, лайки; удаление постов и аккаунта («надгробия»)
  media.js       фото: загрузка, миниатюры, выдача /api/media/<id>.jpg и <id>_t.jpg
  jpeg.js        очистка JPEG (без EXIF/GPS, ICC, комментариев и хвоста после EOI)
  text.js        очистка текста, длина в графемах, ссылки, маскировка мата при выдаче
  moderation.js  журнал, жалобы и автоскрытие, очередь и действия модератора, сводка
  limits.js      ведёрки частоты (в памяти) и дневные пределы (по базе)
  jobs.js        уборка: входы, баны, фото-сироты, сессии, сроки хранения, копия базы
  db.js          social.db и схема (PRAGMA user_version)
server/test/social-smoke.mjs   дымовой тест всех маршрутов
server/test/social-seed.mjs    наполнение для разработки (alice, bob, mia до 18, boss — модератор)
```

Данные: `data/social.db` (одна база на все вузы), `data/media/` (фото), `data/backup/` (копии базы за 7 дней).
Это данные людей: **никогда не удалять их скриптами**, не называть папку исходников `data` или `test`
(deploy.sh исключает обе из выкладки). Копии в `data/backup/` лежат на том же диске, фото в них не входят;
копий вне сервера нет (ночной cron на VPS копирует другой проект) — в публичных текстах их не обещать.

Настройки в `server/.env` (значения вписывает владелец на сервере; `.env` не читать, не выводить, не коммитить):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | пусто | Web-клиент OAuth; пусто — вход «скоро появится» |
| `SOCIAL_ADMIN_EMAILS` | пусто | почты модераторов через запятую |
| `SOCIAL_SALT` | `IP_SALT` | соль отпечатков банов (длинная случайная строка) |
| `SOCIAL_MODE` | `on` | `on` \| `readonly` \| `off` — аварийный выключатель |
| `SOCIAL_MIN_AGE` | `16` | возраст для аккаунта (13–18); тексты политики — то же число |
| `SOCIAL_REPORT_THRESHOLD` | `3` | сколько учитываемых жалоб скрывают пост |
| `SOCIAL_REPORTER_MIN_AGE_H` | `24` | жалобы аккаунтов моложе — не учитываются для автоскрытия |
| `MEDIA_DIR` | `<DATA_DIR>/media` | папка фото |
| `PARA_ORIGIN`, `DEV_LOGIN`, `DEV_HUB`, `SOCIAL_NEW_ACCOUNT_H`, `SOCIAL_RATE_LIMITS`, `SOCIAL_DEV_GOOGLE_TOKEN_URL` | — | только для разработки, в production не действуют |

Аварийный выключатель: `SOCIAL_MODE=readonly` (писать нельзя; жалобы, блокировки, удаление своего и аккаунта,
выход работают) или `off` (обсуждений нет; вход ради удаления, выход и удаление аккаунта работают), затем
`sudo systemctl restart schedule-api`.

Правила обсуждений меняются по существу (`web/src/social/rules.ts`, `server/hub/rules.html`) — **вместе с ними
поднять `social.rulesVersion` в `server/src/config.js`**: все примут правила заново.

Проверка локально (Git Bash; данные — во временной папке, не в `server/data`):

```bash
P=8792; DATA="$TEMP/para-data-$P"; mkdir -p "$DATA"
cd server && NODE_ENV=development DEV_LOGIN=1 DEV_HUB=1 PARA_ORIGIN=http://be.localhost:$P NO_POLL=1 \
  SOCIAL_ADMIN_EMAILS=boss@dev.local SOCIAL_REPORTER_MIN_AGE_H=0 SOCIAL_NEW_ACCOUNT_H=0 \
  PORT=$P DATA_DIR="$DATA" WEB_DIR=../web/dist node --experimental-sqlite src/index.js
# в другом терминале, из корня проекта:
node server/test/social-smoke.mjs http://127.0.0.1:8792 kfu     # «Всё прошло: N проверок.»
node server/test/social-seed.mjs  http://127.0.0.1:8792 kfu     # наполнение для интерфейса (можно повторять)
```

Другие прогоны теста: `SMOKE_NEW_ACCOUNT=1` (сервер с `SOCIAL_NEW_ACCOUNT_H=24`, ≈ 6 минут), `SMOKE_MODE=readonly`
и `SMOKE_MODE=off` (сервер с тем же `SOCIAL_MODE`, после seed), `SMOKE_GOOGLE_PORT=9901` (вход через поддельный
Google: сервер с `GOOGLE_CLIENT_ID=smoke.apps.googleusercontent.com GOOGLE_CLIENT_SECRET=smoke
SOCIAL_DEV_GOOGLE_TOKEN_URL=http://127.0.0.1:9901/token`). Подробности — в начале `social-smoke.mjs`.

## Добавить новый вуз

Пример ниже — вымышленный вуз `tatu` с адресом `tatu.skycoax.uz`. Подставляй реальные.

### Шаг 0. Выяснить источник расписания — от него зависит объём работы

| Источник | Что нужно | Объём |
|---|---|---|
| **EduPage** (`<что-то>.edupage.org/timetable/`) | только папка вуза | ~15 минут, без кода |
| **Google-таблица** | свой Apps Script под раскладку таблицы + папка вуза | зависит от таблицы |
| **Другое** (HEMIS, сайт вуза, Excel…) | новый адаптер `server/src/source-<тип>.js` + папка вуза | программирование |

Проверка, что EduPage публичный (должен вернуть JSON с `regular.timetables`, без входа):

```bash
curl -s -X POST -H "Content-Type: application/json" \
  "https://tatu.edupage.org/timetable/server/ttviewer.js?__func=getTTViewerData" \
  -d '{"__args":[null,2026],"__gsh":"00000000"}'
```

(2026 — учебный год; с августа по июль один и тот же. Если ответ пустой или ошибка
доступа — расписание закрыто, EduPage-адаптер не подойдёт.)

### Шаг 1. Папка и tenant.json

Имя папки = id вуза: латиница в нижнем регистре, цифры, дефис (`tatu`, `samdu`, `tdtu-2`).
Скопируй `server/tenants/tsue/tenant.json` в `server/tenants/tatu/tenant.json` и заполни:

```jsonc
{
  "hosts": ["tatu.skycoax.uz"],          // адрес(а) вуза; первый — основной (canonical, превью)
  "source": { "type": "edupage", "host": "tatu.edupage.org" },
  // или: "source": { "type": "sheets", "url": "https://script.google.com/macros/s/…/exec" }
  "pollMinutes": 30,                      // как часто сверять: 30 для EduPage (данные тяжёлые), 5 для таблицы
  "snapshotKeep": 6,                      // сколько снимков хранить: 6 для EduPage (снимок ~2 МБ), 50 для таблицы
  "site": {                               // для превью ссылки в Telegram и «На главный экран»
    "name": "Расписание ТАТУ",
    "title": "Расписание ТАТУ · Ташкент",
    "description": "Пары своей группы, обратный отсчёт до начала и правки расписания — сразу на телефоне.",
    "appDescription": "Расписание пар Ташкентского университета информационных технологий"
  },
  "brand": {                              // тексты в приложении
    "label": "Расписание ТАТУ · Ташкент", // «Расписание <сокращение> · <город>» — из него же строится пункт меню вузов
    "university": "Ташкентский университет информационных технологий",
    "logoCredit": "Эмблема ТАТУ в шапке взята с … (лицензия …) и показана только чтобы было понятно, чьё это расписание.",
    "about": "Неофициальный просмотрщик расписания … Приложение читает открытое расписание вуза в EduPage и показывает его удобнее. К вузу отношения не имеет и его позицию не выражает.",
    "source": "Расписание принадлежит вузу и публикуется им в EduPage. Приложение только отображает его и ничего в нём не меняет.",
    "sourceShort": "Расписание берётся из открытого расписания вуза в EduPage и может отставать — перед важным решением сверяйся с оригиналом.",
    "searchHint": "Примеры названий групп через запятую…"
  }
}
```

Правила:
- JSON без комментариев (`//` выше только для пояснения — в файле их быть не должно).
- Все поля `site.*` и `brand.*`, кроме `logoCredit`, обязательны — иначе сервер НЕ запустится
  и укажет, какого поля нет. `logoCredit` можно оставить пустым, если логотип свой/без лицензии.
- Адрес не должен повторяться у двух вузов.
- В `about` обязательно слово «неофициальный» и что приложение к вузу отношения не имеет.
- Если в EduPage пары чередуются по неделям, в `brand.source` добавь фразу про недели A и B
  (см. `tsue/tenant.json`).
- `searchHint` — посмотри реальные названия групп (шаг 4) и дай 2–3 примера.

### Шаг 2. Картинки бренда

Нужен знак вуза (эмблема без надписи по кругу) — цветной на белом или прозрачном фоне.
Всё, что темнее фона, станет формой; белый логотип на прозрачном фоне НЕ подойдёт.
Источник логотипа — Wikimedia Commons или официальный сайт вуза; впиши лицензию в `brand.logoCredit`.

```bash
pip install pillow numpy          # если ещё не стоят
python server/tenants/_tools/brand-images.py \
  --logo путь/к/знаку.png \
  --out server/tenants/tatu \
  --title "Расписание ТАТУ" \
  --subtitle "Пары своей группы и отсчёт до начала — на телефоне" \
  --host tatu.skycoax.uz \
  --og-logo путь/к/полному-логотипу.png   # необязательно: цветной логотип для превью ссылки
```

Должно появиться 7 файлов: `logo-mark.png`, `og.jpg`, `icon-192.png`, `icon-512.png`,
`icon-maskable-512.png`, `apple-touch-icon-dark.png`, `apple-touch-icon-light.png`.
Если у логотипа есть круговая надпись — сначала обрежь до центрального знака
(на 40 px в шапке мелкий текст превращается в кашу). Посмотри `logo-mark.png` глазами.

### Шаг 3. Проверка локально (обязательно до выкладки)

```bash
cd web && npm install && npm run build && cd ..
cd server && npm install
PORT=8792 DATA_DIR=/tmp/sched-test WEB_DIR=../web/dist DEV_TENANT=tatu \
  node --experimental-sqlite src/index.js
```

Сервер при старте проверяет все `tenant.json`; ошибка в настройках — сразу понятное сообщение.
В другом терминале (вуз выбирается заголовком Host; первый опрос EduPage — несколько секунд):

```bash
B=http://127.0.0.1:8792; H="Host: tatu.skycoax.uz"
curl -s -H "$H" $B/api/health                                  # tenants: есть tatu, lastPoll не null
curl -s -H "$H" "$B/api/schedule?group=" | head -c 600         # ready: true, groups не пустой
curl -s -H "$H" $B/ | grep -o "<title>[^<]*</title>"           # название вуза
curl -s -o /dev/null -w "%{http_code}\n" -H "$H" $B/brand/logo-mark.png   # 200
curl -s -H "$H" $B/api/universities                            # новый вуз в списке
```

Проверь по ответу `/api/schedule?group=`:
- поля `sheet` (разделы: «1 курс», «Магистратура · 1 курс»…) и `sub` (факультет) выглядят разумно;
- у выбранной группы (`?group=<key>`) есть `days` и `times`, в ячейках текст вида
  «Предмет · ауд. 1/111 · Преподаватель».

Разделы и факультеты EduPage восстанавливаются по строкам-заголовкам в списке классов
(«MENEJMENT FAKULTETI», «1 KURS», «MAGISTRATURA 1 KURS»…) — логика в
`source-edupage.js` (шаг 4 функции `fetchEdupage`). Если у нового вуза заголовки названы иначе
и группы попали в «Другие группы», дополни распознавание там, НЕ ломая ТГЭУ
(перепроверь `tsue` той же командой).

Интерфейс можно открыть в браузере: `http://localhost:8792/` покажет вуз из `DEV_TENANT`.

### Шаг 4. Выкладка

Нужен SSH-доступ по ключу к `ubuntu@46.8.195.171` (есть на компьютере владельца;
в облачной песочнице агента его нет — тогда выкладку запускает владелец).
Из корня проекта, в Git Bash (Windows) или обычном bash:

```bash
bash deploy/deploy.sh
```

Скрипт собирает сайт, заливает сервер вместе со всеми `tenants/`, ставит зависимости,
перезапускает `schedule-api` и печатает health. Sudo-пароль не нужен.

### Шаг 5. Проверка на проде

```bash
curl -s https://tatu.skycoax.uz/api/health
curl -s "https://tatu.skycoax.uz/api/schedule?group=" | head -c 300
curl -s https://kfu.skycoax.uz/api/universities   # новый вуз виден и из других вузов
```

Открыть `https://tatu.skycoax.uz` на телефоне (или в эмуляции 375×812): согласие → выбор
группы (чипы разделов, факультеты) → шапка с логотипом → нажатие на логотип показывает
меню вузов. Проверь, что КФУ и ТГЭУ по-прежнему открываются.

Если служба не поднялась после выкладки: `ssh ubuntu@46.8.195.171 "sudo systemctl status schedule-api"`
(разрешено без пароля) — в последних строках будет причина, чаще всего ошибка в `tenant.json`.

## Если источник — Google-таблица

Сервер не читает таблицы напрямую (они обычно закрыты). Нужен Apps Script, развёрнутый
как веб-приложение от имени владельца таблицы, который на `GET <url>?fn=data` отвечает:

```json
{ "ok": true, "data": {
  "header": "Расписание с 07.09.2026 …",
  "fetchedAt": "2026-09-14T10:00:00.000Z",
  "groups": [{
    "key": "1 курс :: Геология",       // стабильный уникальный ключ — сохраняется у студентов, не менять
    "sheet": "1 курс очное",           // раздел в выборе группы
    "course": "1",
    "name": "1 курс Геология 05.03.01",
    "sub": "",                         // необязательно: подраздел (факультет)
    "link": "",                        // необязательно: ссылка на онлайн-занятия
    "times": ["08:30 – 09:50", "10:00 – 11:20"],          // по одному на пару
    "days": [{ "day": "Пн", "pairs": ["Предмет 108 ауд. Иванов И.И. доц.", ""] }]
  }]
}}
```

`day` — «Пн»…«Сб»; `pairs` — столько же ячеек, сколько `times`; пустая строка = нет пары.
Текст ячейки разбирается на предмет/аудиторию/преподавателя эвристикой (`web/src/lib/parse.ts`);
надёжнее отдавать формат «Предмет · ауд. 108 · Иванов И.И.».
Образец под таблицу КФУ — `apps-script/Code.gs` (`parseSource_` и `doGet` с `fn=data`);
для другой таблицы раскладку придётся переписать под её строки и столбцы.

## Если источник другой

Создай `server/src/source-<тип>.js` с функцией, возвращающей
`{ header, fetchedAt, groups, weeks?, weekMap? }` в той же форме, что выше
(для чередования недель — `weekDays: [[…дни недели A], […недели B]]` вместо `days`,
`weeks: ["Неделя A", "Неделя B"]` и `weekMap: { "2026-09-07": 0 }`; см. `source-edupage.js`),
подключи в `server/src/source.js` новым `source.type` и добавь проверку полей в `check()` в
`server/src/tenants.js`.

## Отключить вуз

В его `tenant.json`: `"enabled": false`, затем `bash deploy/deploy.sh`. База остаётся.

## Общие правила для агента

- Интерфейс и тексты — на русском; стиль — сдержанный, как в системных приложениях Apple
  (без ярких «ИИ-шных» подсветок, свечений, градиентных плашек).
- Бренд вуза не хардкодить во фронте: всё — через `tenant.json` и `web/src/brand.ts`.
- Не менять `key` групп у существующих вузов: по нему у студентов сохранён выбор группы.
- Не трогать nginx, DNS, сертификаты, systemd на сервере — для нового вуза это не нужно.
  Любые команды с `sudo` (кроме `systemctl restart|status schedule-api`) требуют пароля владельца:
  подготовь скрипт и попроси владельца запустить его сам через `ssh -t`.
- Секреты (токены, пароли, `server/.env`) не выводить в лог и не коммитить.
  Если владелец прислал токен в чат — не использовать, попросить отозвать и ввести новый сам.
- Изменение в `server/src/*` влияет на ВСЕ вузы: после правок проверяй `kfu` и `tsue` тоже.
- Перед выкладкой: `cd web && npx tsc --noEmit && npm run build`, `for f in server/src/*.js server/src/social/*.js; do node --check "$f"; done`
  (`node --check` со списком файлов проверяет только первый).
